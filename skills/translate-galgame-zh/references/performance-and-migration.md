# 性能观测与 v3 迁移

## 先区分计量

磁盘产物大小不等于模型输入，代理 tokenizer 不等于宿主 usage，缓存命中不等于免费或释放上下文。记录普通输入、缓存读、缓存写、输出及推理细分；输出已含推理时不能重复相加。未知字段用 null。

主指标是每万原文字符的已批准译文成本、每小时完成的已批准原文字符数，以及关键语义错误和返工率。另记冷/热态、首响应、完整任务 p50/p95、审校队列和恢复成本。不能把局部建包加速比例宣称为整个游戏的加速比例。

## 可直接使用的优化

- 按角色读取资料，不让翻译者重新读取研究、协调和发布手册。
- 前缀只含生效语义。保持来源、日志、pending 与测量在机器侧；不反复输出完整译文。
- 正常译文仅 id/translation，issues/term_proposals/confidence 只在需要时提供；旧的完整行格式仍可验证。
- 用 `build_context_bundle.py --jobs …` 或 `--all-pending` 批量处理。一个批次缓存读入与 JSON 解析结果，结束时检查输入是否变化；不跨运行盲目复用 mtime。
- 不变输入不重复跑同一确定性规则。收据应绑定材料、规则与验证器版本；发布前保留全量 QA。
- 对目录只合并当前任务清单批准的文件，避免旧备份参与构建。

依赖审计不会自动应用裁决或改变任务状态。profile/闭包选择由主协调者负责，确定性工具检查结构和摘要，不能证明语义闭包完整。

## v2 项目的兼容边界

v3 保留既有源 ID、草稿行格式和阶段名称，但任务包、审校声明与合并接口更严格。升级技能不自动修改任何游戏项目。

1. 备份项目状态和原有快照；运行审计，盘点已有草稿与批准稿。
2. 保留旧 jobs，按新定义重新编译生效前缀。旧 decision digest 若是完整原始 JSON 摘要，需要协调者确认对应生效内容后迁移到新 manifest 的决策摘要；不能静默改写。
3. 对需要继续执行的任务重新建 v3 bundle；旧 v2 bundle 会被明确拒绝派发。新入口是 `contexts/<job>/current.json`，原来的平铺文件不会删除，但不再作为当前任务入口。
4. 校核旧草稿与原文摘要、上下文及依赖后可复用语言内容，无需因结构升级自动重译。无有效独立审校声明的旧批准稿需要补足审校证据；不能给缺失身份或 coverage 的旧报告自动补一个 passed。
5. 后续独立报告使用 `create_review_report.py`；`apply_review_delta.py --report …` 读取声明，生成单独的 `.report.materialization.json`。旧 `--verify-existing-report` 仍可传，但是否传入都要求声明存在并通过。
6. 合并必须传 `merge_jobs.py <source> <approved-dir> <output> --jobs-jsonl <jobs>`。任务状态、条目覆盖、批准稿及审校收据必须一致。
7. 缓存计数改为逐请求；旧 `--calls` 仅允许 1，多请求使用 `--usage-jsonl`。仅有文件边界估算时记录 observed-only。
8. 发布前补齐绑定当前构建的字体和实机证据。合成测试夹具不能迁移成发布证据。

## 回归入口

运行 `python -B scripts/tests/test_pipeline.py`。测试只使用独立合成目录，覆盖分批预算、资料变化、快照完整性、独立审校、合法状态迁移、缓存观测与批量建包；不启动真实游戏或调用翻译服务。另按目标引擎进行实际回填与游玩验证。
