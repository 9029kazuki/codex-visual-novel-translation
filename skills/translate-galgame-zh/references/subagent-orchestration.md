# 场景任务与子智能体编排

## 角色与边界

主智能体维护资料库、任务计划、状态和交付；研究者只返回证据；翻译者处理一个批准场景；独立审校者对照原文、冻结资料和草稿检查完整场景。翻译者与审校者使用不同身份，不继承对方的解释和推理。

使用真实原生子智能体。不可用时记录降级原因，主智能体按相同文件协议顺序执行，并明确审校独立性受限；不能伪造另一位审校者身份通过独立门禁。

## 任务与依赖

以场景为单位：连续的时间、地点、视角和人物组合可合并；父选择、各分支和合流点要明确记录条件。公共复用资源由唯一任务处理。同一原文在不同场景出现不自动视为同一语义。

`plan_jobs.py` 生成新建议文件；主智能体检查场景图与边界原文后，填写 `plan_approved`、`prior_summary`、`predecessors`、`adjacent_entry_ids`、时间、地点和 `context_notes`。无额外上下文需求时说明原因。原文 ID 集合不变时，任务身份不会因前面新增一个场景而整体重编号。

依赖范围默认全项目。使用选定 profile 或 job `dependency_scope` 前，明确批准间接角色、知识门、其他路线和额外术语作用域的闭包。无法确定闭包时继续使用全项目资料，不为了 token 任意省略。

## 准备与派发

1. 冻结生效资料与决策，建立共享前缀。
2. 用 `build_context_bundle.py <project> --all-pending` 或 `--jobs …` 批量建包；一次全局检查和输入读取服务一批任务。
3. 按 [shared-prefix-and-batching.md](shared-prefix-and-batching.md) 管理稳定初始化、真实预算与短生命周期 cohort。机器计划和摘要先在脚本中校验，不把全部清单反复读入模型。
4. 只派发上下文已备齐的任务；状态由主协调者更新。每个 worker 只写自己的任务目录。
5. 收到一项草稿即验证并排入审校；错误按 ID 和规则反馈，不重新附带全部主任务历史。

翻译执行模板：

```text
你是翻译执行者。使用指定的冻结资料和翻译契约，不承担项目研究或协调。
逐个读取经 emit_chunk.py 校验的 packet，仅为 primary ID 输出紧凑 JSONL。
overlap 与 adjacent 仅用于理解。保持控制符和必要换行；不改共享资料或最终脚本。
每批写独立文件，核对覆盖后汇总到指定 drafts 文件，运行结构验证。
结束时只返回路径、条数、问题 ID 和术语提案，不复述全部译文。
```

独立审校模板：

```text
你是独立审校者，读取指定冻结资料、完整场景原文和草稿，不读取翻译者解释。
检查事实、否定/使役、主体、知识状态、人物口吻、称谓、术语和控制符。
完整阅读所有分批，只把需修改行写入 sparse delta；无修改时可为空文件。
阅读与裁决完成后，用 create_review_report.py 明确声明 all-entries、真实双方身份和 outcome。
有待主协调者裁决的问题时 outcome=needs-resolution，不能写 passed。
不修改原草稿、共享资料或批准稿。返回 delta/report 路径和未解决 ID。
```

`create_review_report.py` 只计算材料摘要并记录审校者声明，不替代阅读。主协调者用 `apply_review_delta.py` 检查声明后物化批准稿；报告缺失、失败、身份相同或摘要变化都会阻断。再次审校使用新的尝试文件，保留旧声明，再由协调者选择有效尝试作为任务的规范报告。

## 变更、吞吐量与恢复

资料变化后运行 `audit_dependencies.py`，只对实际失效任务定向修订/审校。不要把所有 job 强制绑定 current 前缀。新快照可以先服务未开始任务；批准稿与旧证据继续保留。

按真实平均耗时平衡翻译和审校容量，预留协调与必要 seed 槽位。审校积压时停止继续灌入草稿。相同模型、工具配置和 profile 的依赖就绪任务尽量连续运行；不要为了缓存打乱语义依赖，也不要把宿主当前并发槽位数硬编码进技能。

中断后检查已有分批的内容摘要、primary 覆盖和验证收据，复用完整部分，只重做缺失或失败部分。`set_job_status.py --invalidate --note …` 允许带原因回到 pending；普通迁移必须符合状态图。任务表保持单写者；原子替换不能替代多个并发写者之间的事务协调。
