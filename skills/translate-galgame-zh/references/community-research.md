# 多语言社区与官方资料研究规范

## 研究边界

把“事实与技术取证”和“目标中文本地化惯例”分开：

- 引擎、解包、封包、字体、世界观、人设、关系、口吻和剧情知识状态的研究不限语言。无论中文、日文、英文或其他语种，只要证据更原始、更权威、更符合准确版本，就应当优先。
- 只有在裁定简体中文译名、历史汉化惯例、中文语域可接受度和系列官方中文连续性时，才把中文资料作为必要语域证据。
- 语言不是权威度。游戏本体和官方材料高于二手社区转述，无论它们用什么语言发布。

在解包前和冻结资料库前分别执行一次研究，后续剧情内证可以触发定向补证。

## 研究分线

1. **`engine` 引擎与工程线**：搜索准确游戏版本、引擎、归档扩展名、工具支持情况、文本格式、回填、封包、签名和字体问题。使用所有可找到的技术社区、工具文档、代码仓库和实测证据。
2. **`canon` 作品事实与口吻线**：从游戏内文本、官方网站、制作方资料、设定集、访谈、Wiki、攻略和玩家考据中总结世界观、角色关系、读音、第一/第二人称、语尾、敬语层级、口癖和剧情知识门。不限日文。
3. **`target-locale` 目标中文惯例线**：重点搜索官方简/繁中文、同系列中文产品、成熟汉化、中文条目、攻略与讨论，确定作品名、人名、地名、组织、称号、招式、专有词、称谓和中文标点惯例。

可并行委派三条线，但主智能体必须交叉核对、裁决冲突并合并资料库。旧项目中的 `unpack`、`jp-canon`、`zh-terminology` 仅作兼容别名；新项目使用上述三个新 lane。

## 查询方法

同时使用原名、罗马字、官方英文名、实际发行地语名、品牌名和准确版本号。根据证据所在语域翻译查询词，例如：

```text
作品名 版本号 engine unpack repack script font archive
作品名 エンジン 展開 抽出 シナリオ アーカイブ
作品名 character profile world setting pronoun speech pattern interview
作品名 キャラクター 設定 世界観 口調 一人称 二人称
作品名 人名 地名 术语 汉化 译名 攻略 设定
系列名 官方中文 旧汉化 常用译名 人名对照
```

若只找到笼统教程，继续搜索“准确版本＋实际扩展名/文件签名”。不把另一版本或同引擎其他游戏的方法写成已验证结论。

## 来源优先级

### 工程事实

1. 对目标版本的只读实测、工具源码/官方文档、文件头和归档索引证据。
2. 相同版本的完整成功案例。
3. 相同引擎或相近版本的方法，必须标记为待在副本验证。

### 作品事实、人设与读音

1. 游戏本体、官方网站、官方设定集和制作方材料。
2. 可追溯到原始材料的高质量 Wiki、攻略站、访谈整理和考据。
3. 多个独立社区来源一致的转述。
4. 无来源转载或单一帖子。

### 简体中文译名与汉化惯例

1. 已存在的官方简体/繁体译名及同系列官方译名。
2. 成熟汉化版本、汉化组公开术语、被广泛采用的社区译名。
3. 中文攻略、Wiki、条目、论坛或视频社区中的多处一致用法。
4. 主智能体根据含义、读音、系列连续性和中文风格作出的新译名。

“官方事实来源”和“中文使用惯例来源”可以不同。前者负责确认事实、含义与读音，后者负责确认中文玩家实际使用的译名。

## 研究记录

把每个来源作为一行写入 `research/sources.jsonl`。新项目的 `lane` 使用 `engine`、`canon` 或 `target-locale`；每条线至少有一项有效来源。最小记录：

```json
{"url":"https://example.invalid/page","title":"页面标题","source_language":"en","source_type":"official-interview","authority":"official","retrieved_at":"2026-08-18T00:00:00Z","lane":"canon","claims":["角色的第一人称为……"],"scope":"全系列","confidence":"high","notes":"原始访谈"}
```

必填字段：

- `url`、`title`、`retrieved_at`、`lane`、`claims`、`scope`、`confidence`。
- `source_language`：BCP 47 或项目约定语言标签。旧项目的 `language` 可兼容读取，新记录使用 `source_language`。
- `source_type`：如 `game-text`、`official-site`、`official-interview`、`tool-docs`、`source-code`、`wiki`、`community-post`、`local-test`。
- `authority`：`primary`、`official`、`maintainer`、`secondary`、`community` 或 `local-test`。

在 `research/decisions.md` 记录冲突裁决；至少写明候选、各自来源、选择结果、适用范围和复查条件。

## 资料库要求

### `characters.json`

每个角色至少记录：

- 原文名、读音、中文锁定名和别名。
- 性别呈现、年龄阶段、身份、阵营和人物关系。
- 第一人称、第二人称、他称、称谓变化和敬语层级。
- 常用句式、语尾、口癖、禁用表达和代表性原文/译文。
- 不同路线或时间段的知识状态与性格变化。
- 来源 URL、证据语言和置信度。

### `voice.json`

记录旁白及每个角色的中文表达目标：句长、正式度、文雅/口语程度、攻击性、可用网络词程度、是否保留敬称、情绪升高时的变化。口吻描述必须附短例句，避免只写“温柔”“傲娇”等抽象标签。

### `glossary.tsv`

使用列：

```text
source\ttarget\treading\tcategory\tstatus\tscope\tsource_url\tnotes
```

`status` 使用 `locked`、`preferred`、`proposed`、`forbidden`。锁定项未经主智能体裁决不得被子智能体更改。记录同形异义和仅限特定路线、场景、时代或说话人的作用域。

## 综合规则

- 不以搜索结果摘要代替打开原页面。
- 不因单一帖子声量大就锁定事实或译名；尽量找两类独立证据。
- 找不到约定译名时保留多个候选，先在校准场景验证。
- 中文惯例与原始证据冲突时不静默选择；在决策记录中说明取舍。
- 后续游戏内文本推翻社区说法时，以游戏内证据修订，并递增资料库版本。
