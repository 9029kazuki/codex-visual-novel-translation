# 日译中 Skill 修订 3

本次将已经验证的本地修复合入 `skills/translate-galgame-zh`。公开版保留原名称、界面信息及外部 GARbro 定位方式，不分发 GARbro 二进制。本轮验证和下列测量针对日译中版；国际版维持独立版本。

候选版本与本地安装版本均通过 24 项回归测试，技能结构验证通过。可下载 [流程演示](demo.html) 后在浏览器打开；可编辑源文件为 [demo.fragment.html](demo.fragment.html)。

**这次落地的修改**

| 范围 | 修复后的行为 |
| --- | --- |
| 指令加载 | 入口按新建、恢复、局部修订、只读审计分流；翻译者只读翻译所需参考，不重复加载协调、研究和发布说明。 |
| 冻结与依赖 | 每个 job 绑定自身前缀和语义依赖。新的 current 指针不使旧 cohort 整体失效；任务上下文、原文或相关规则变化才要求处理。完整项目依赖为默认，可显式批准更小的依赖范围。 |
| 前缀稳定性 | 结构化来源记录、检索时间、pending/proposed 和运行测量不进入生效正文；相同正文与不同物理来源绑定分别标识，避免不可变 manifest 冲突。独立模式仍携带冻结决策。 |
| 分块 | 计算实际序列化 packet、共享资料、邻接原文、可配置宿主开销并预留输出。必要材料或单条原文超限明确失败，可选重叠可缩减。每个原文 ID 只有一个 primary 所有者。 |
| 快照可靠性 | 写入独立快照并逐文件读回验证，全部成功后才切换 current。损坏、修改或部分写入不能借用旧 valid 状态；失败保留旧快照。 |
| 输出与读取 | 常规译文只需 id/translation；空 confidence、issues、term_proposals 不再强制重复输出。emit_chunk 只读取当前分块；元数据和全量覆盖清单由机器保管。 |
| 批处理 | 一次调用可建多个 job，共享文件读取与 JSON 解析；批末重新核对输入，避免跨运行仅依赖 mtime 的陈旧缓存。 |
| 独立审校 | 声明需要不同译者/审校者身份、完整覆盖、原文/初稿/delta 摘要；缺失、失败、过期声明不能生成批准稿。声明与物化收据分开保存。 |
| 试跑反馈 | 提前校验 delta 的字段、控制符和 minor/major 枚举；修复兼容参数说明；补齐旧尝试归档、重新声明和选取当前合并产物的流程。 |
| 自动 QA | 修复同一句中长短术语的独立出现被错误豁免；按场景/说话人/路线约束重复译文比较。全局报告绑定原文、译文和术语内容摘要。 |
| 状态与合并 | 限制合法状态迁移，支持单写者批量状态更新；按批准任务清单和收据合并，忽略历史备份。稳定任务 ID 不因前面插入新场景而整体改名。 |
| 字体与发布 | 同时要求字体静态覆盖和运行时报告；绑定封包构建，检查新旧配置中的六类文字界面及真实存在的证据路径。工具自测不会代替实机验证。 |
| 缓存观测 | 逐 request_id 去重、拒绝冲突和累计计数；分别记录输入、缓存读、缓存写、输出，未知为 null。多次请求的总命中不能证明某一次完整前缀命中。 |

**性能与 token 实测**

| 测量 | 结果 | 适用边界 |
| --- | --- | --- |
| 本地原版 SKILL.md 全文代理 token | 2,068 → 1,609 | o200k_base 代理计数；不是 Codex 的真实上下文或账单。 |
| 匹配任务的建包耗时 | 3.06 秒 → 1.76 秒，减少约 42.6% | 相同 20,000 条源文件、100 个计划任务，构建同样的前 10 个任务/2,000 条。新版本保留更严格预算和完整性检查；单次本地样本，不代表整部作品吞吐。 |
| 源 JSONL 解析工作量 | 600,000 条 → 20,000 条，减少约 96.7% | 新版总 JSONL 解析量 20,104 条，还包括任务表和研究/校准记录。输入快照读取含 27 次批末复核，不能误记为没有复读。 |
| 全量建包样本 | 20,000 条、10 个大任务，340 块，8.59 秒 | 与上一行只处理 2,000 条的耗时不能直接比较。预算更严格会增加分块和文件校验工作。 |
| 短句压力场景 | 20,000 条「え？」、40,000 字符 → 164 块 | 默认 UTF-8 字节规划估算；最高估算输入 10,452、输出 8,174，分别不超 32,000 / 8,192。无宿主历史的分块函数测试，不宣称实际模型窗口已验证。 |
| 真实模型 token、缓存和费用 | 未测得 | 没有将文本哈希或代理 token 伪装成 usage；不宣称缓存命中率或订阅额度节省比例。 |

缓存复用仍受实际消息顺序、系统与工具定义、历史、宿主路由等影响。控制请求里的动态内容、采用短生命周期 cohort、避免全主对话继承已写入流程。缓存不会释放窗口。实现保留原生子智能体翻译，没有改成外部翻译 API。

**虚构作品的实际试跑**

《风停之前》有公共段、美咲分支和玲分支，共 9 条日文原文。独立审校者完整阅读全部 9 条，输出 2 条修订，其余 7 条保留；三个任务的批准稿和物化收据均已生成，最终合并 9 条，全局 QA 为 0 错误、0 警告。

例如 `忘れたわけじゃない。ただ、言えなかった。[wait]` 的初稿把否定误译为“我已经忘记了”。审校修订为“并不是忘了。只是，没能说出口。[wait]”，同时保持控制符。另一处修订恢复了 `約束する` 在对话中“当场承诺”的含义。

这说明自动结构检查通过不等于翻译语义正确：初稿的自动 QA 同样没有发现上述语义问题，独立全场景审校仍有必要。

另在隔离副本新增玲线专属术语，实测依赖审计仅要求 job-0002 处理，job-0000 与 job-0001 继续复用旧快照。交互演示共 10 步，已在 736px / 360px、浅色 / 深色下检查全部 40 个状态，无脚本错误、文字越界或横向溢出。

**升级及使用边界**


已有 v2 项目继续执行前，需要按技能的 [performance-and-migration.md](../skills/translate-galgame-zh/references/performance-and-migration.md) 重建 v3 任务包，并核对旧决策摘要与独立审校声明。旧草稿不因结构升级自动重译，缺失的审校/发布证据也不会自动补成通过。新增 merge 的必需参数为 `--jobs-jsonl`；旧 `--calls` 只接受 1，多请求使用 `--usage-jsonl`。

依赖闭包仍需协调者审阅，脚本不能推导完整剧情语义；全部生效决策目前保守保留，不自动按路线裁剪。真实模型窗口、上下文成本、缓存命中、端到端吞吐还需要在目标宿主的真实长场景中测量。具体游戏的解封包、字体加载、路线、存读档与安装测试仍需执行，当前演示没有生成可发布补丁。
